# 未来的安装与升级流程

**这是规划中的用户体验，不是当前可执行安装教程。** 正式 Installer 和 Community release 尚未发布，目前没有一键安装命令。

目标是少填参数、清楚知道每一步、失败能恢复。您不需要把 HA 密码、中控 SN 或其他敏感凭据交给项目维护者。

## 场景一：已经有 Home Assistant 和正常工作的 NEXhome

未来流程：找到并确认您的 HA → 展示将做的变更 → 取得必要授权 → 识别现有版本和更新来源 → 备份 → 安全升级 → 检查结果。

- 不重新创建第二套设备。
- 不重新 discovery 并覆盖正常配置。
- 尽量保留原 config entry、实体标识和设备关系。
- 如果现有实体需要改成另一种类型，另给迁移预览，不在普通升级时强制改掉旧自动化引用。
- 升级失败时恢复旧组件及原更新所有权，说明是否已验证恢复。

如果现有 NEXhome 不正常，先保留配置、判断错误。只有确认连接参数需要修复时，才重新查找中控；不直接删除旧配置。

## 场景二：已有 Home Assistant，但没配置 NEXhome

未来流程：确认 HA → 授权并安装 Community 组件 → 由 HA 在本地查找中控 → 初始化设备 → 检查结果。

真实环境已验证：HA Core 可以通过本地 NSDP 广播取得中控 IP:PORT 和所需 SN/IOTID。正常情况下不要求手工填写这些参数。

- 没找到中控：解释如何确认同一家庭网络、中控供电及网络隔离，不偷偷遍历家庭主机。
- 找到一台：显示找到的中控并在本次授权范围内继续。
- 找到多台：让您选择，不能替您猜。

多 Hub、跨 VLAN 和其他型号/固件仍需进一步测试；不是所有网络都已验证免参发现。

## 场景三：还没有 Home Assistant

未来入口先判断宿主平台和资源。通过预检且属于已支持的平台时，才在您确认后准备 HA。

首个拟议新建适配器是窄范围的 Linux + 已有 Docker Engine。群晖、PVE 和软路由需要各自适配与验证，不因为“有 Docker”就自动安装。软路由存储或资源不合适时必须停止，避免影响家里的网络。

暂不支持自动安装的平台：给您对应指导 → 先完成 HA 安装和首次账号设置 → 重新运行入口 → 继续统一的 NEXhome 接入流程。保存可继续的进度，不让您反复从头开始。

没有可用宿主时，需要先准备合适设备；工具不会自动重装路由器或替您格式化硬盘。

## HACS 与非 HACS：更新只能由一方负责

HACS 不是 NEXhome 运行前提。

| 当前情况 | 未来处理方式 |
|---|---|
| 官方 HACS 管理 | 先备份，再安全切换到 Community HACS 或 Installer；切换未完成时不覆盖文件 |
| Community HACS 管理 | 后续更新走 HACS；Installer 只检查/诊断，不另写一份组件 |
| 没有 HACS | Installer 可直接部署并负责以后经您确认的更新，无需先装 HACS |
| 手工安装或来源不明 | 先识别和备份，让您确认后才接手更新 |

如果 HACS 来源切换不能可靠自动完成，工具会给一个清晰、与您版本匹配的最少步骤，而不是偷偷保留“官方更新源 + 本地补丁”。不要把“切换下载来源”误操作为“删除 HA 中现有 NEXhome 配置”。

首版不后台静默更新；发现新版后，说明版本、改动和恢复方式，您确认后才升级。

## 您看到的最终结果

- **SUCCESS：** 本次本地接入或升级通过检查。
- **PARTIAL：** 已安全完成部分步骤，还有明确事项待处理。
- **ROLLED BACK：** 新版本未通过，旧版已恢复并核验。
- **MANUAL ACTION REQUIRED：** 需要您完成清楚列出的一步授权、来源切换或恢复。

成功不等于默认测试过每盏灯或每台空调的物理动作。安装检查不应主动控制家里的设备。

默认不修改您的 Area、Dashboard、Automation、账号、家庭成员或网络设置。可选房间和页面整理必须另外预览确认。
