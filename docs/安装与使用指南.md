# NexHome 滨融府友邻加强版：安装与使用指南

面向已经有可用 Home Assistant 的滨融府住户。产品 **0.1.0 — RELEASE CANDIDATE**，基于官方组件 v1.1.16，已完成内部 RC 验证，尚未正式公开发布；不是 NexHome 官方新版。

当前内部固定包仍需由维护者提供和准备，本文不提供不存在的公开下载地址。不要运行陌生群里的安装链接。本轮只整理文档，没有重新操作测试或生产环境。

<a id="choose-route"></a>
## 一、第一步：判断自己的 Home Assistant 类型

### 1. 先打开自己的 Home Assistant

使用自己的管理员账号登录。没有正常可用的 HA 时，先请本机维护者完成 HA 安装；本项目不替您安装 HA、NAS、PVE、Docker Host、路由器或公网。

### 2. 到“系统信息”看一行字

1. 在 HA 左侧点 **设置**。
2. 点 **系统 → 修复**。
3. 点右上角 **⋮ → 系统信息**。
4. 找 **安装类型 / Installation type**，只按这一行选择路线，不按机器品牌猜。

![HA 设置入口，沿用既有隔离测试截图](manual-images/settings.png)

![官方系统信息示例：查看 Installation type 一行](manual-images/system-information-official.png)

上图来自 [HA 官方系统信息说明](https://www.home-assistant.io/more-info/system-information/)，是官方示例，图中版本和语言可能不同于您自己的 HA；不是本轮新增的 VM 截图。2026.10.x 的菜单路径同上。不要根据图中“Docker: true”选路线，**只看 Installation type**。

| 安装类型显示什么 | 您只需选择 |
|---|---|
| Home Assistant OS | **[A：App 路线](#route-a)** |
| Home Assistant Container（包括装在 NAS / Docker / Linux 中的 Container） | **[B：Terminal 路线](#route-b)** |
| 其他类型，或找不到这一行 | 先让本机维护者确认能否使用 Terminal；不是已经验证所有平台，暂不执行命令 |

**两种方式只需要选择一种。App 和 Terminal 是两个安装入口，不是前后两个步骤。** NAS 或 Linux 是机器环境；如果上面实际显示 Home Assistant OS，仍选 A。

### 3. 两条路线最终会合

**A：HAOS App** 或 **B：Terminal** → 同一个 Neighbor Edition 0.1.0 → HA 加载 → 新安装自动查找中控 → HA 原生确认 → 设备出现 → 首次控制及真实读回 → 确认知道控制入口 → **READY**。

已有安装沿用原 entry，不重复发现或添加中控。看到“组件已部署”还没结束，不能省略设备可见和首次使用确认。

### 4. 两条路线都要做的准备

先保留 HA 备份；确认 HA 与 NexHome 中控在家庭网络中能通信。典型单中控环境通常不用先查 Hub IP、IOTID 或 SN。跨网络无法发现时，不会偷偷修改您的网络。手机端使用官方 Home Assistant App，详见后文。

<a id="route-a"></a>
## 二、A：Home Assistant OS — App 路线

**选了 A，就不用再执行第三节 Terminal。**

### A1. 找到并打开安装助手

1. 打开 **设置 → 应用 / Apps**。
2. 在当前内部维护者已准备的来源中，找到 **NexHome 滨融府友邻加强版**，点开详情。
3. 点 **安装**，等待出现 **启动**，再点 **启动**。
4. 看到“运行中”后，点 **打开网页界面**（部分语言显示“打开界面”）。

应看到欢迎页和“开始检查”。如果列表中没有这个助手，先联系提供内部固定包的维护者；当前没有公开商店 URL，不要猜地址或改走陌生脚本。

![应用入口，既有隔离环境截图](manual-images/apps.png)

### A2. 检查自己的安装

点 **开始检查**。正常时会显示检测结果，以及安装或已有安装的下一步。先读结果，暂不反复点。

如果出现来源不明、HACS 与其他工具管理冲突，或恢复未完成，停止并让维护者核对。已有配置不要删除重建。

![安装助手检查](manual-images/installer-check.png)

### A3. 确认安装

阅读将备份和可能短暂重启 HA 的提示，再点界面的确认按钮。应看到执行进度，随后进入连接或已有设备页面。

重启时页面可能断开。重新打开自己的 HA 和助手，继续核对已有进度；如果要求登录，用自己的 HA 账号登录。**不要因此再安装一遍。**

![确认部署](manual-images/installer-confirm.png)

### A4. 进入统一的连接与首次使用流程

新安装看到 **组件已部署，接下来连接中控** 时，点 **开始连接 NexHome**，进入 HA 原生窗口。按第四节确认中控，再按第五节查看设备、操作一盏灯并返回确认。

已有正常配置会沿用原 entry，直接核对设备；不再添加一个重复中控。即使看到“已有最新版本”，也要核对设备和首次使用是否完成。

**现在跳到[第四节：连接家里的 NexHome](#connect-home)，不执行 B 路线。**

![部署后开始连接](manual-images/deployed.png)

<a id="route-b"></a>
## 三、B：Container / Docker / NAS / Linux — Terminal 路线

**选了 B，就不用再安装 A 路线的 App。** 两条路线不会叠加成“更完整”的安装。

### B1. 先找到输入命令的窗口

按自己已有的管理方式选择一项：

- **NAS 有自带“终端 / Terminal”或 Docker 管理终端**：从 NAS 的已有管理界面打开，由本机维护者确认这是管理 HA 所在主机的窗口。
- **Linux 主机或虚拟机有本地桌面 / 控制台**：打开已有的 Terminal，由本机维护者进入已经准备好的安装执行环境。
- **平时由维护者通过 SSH 管理**：使用对方原来就能登录的终端入口。不会 SSH 时让维护者协助，不为本教程新开公网端口或修改路由器。
- **只有 HA 网页，不知道主机入口**：先暂停。HA Container 的网页不会自动提供一个具有主机管理权限的 Terminal，不要随便进入某个无关容器。

### B2. 拿到“本机已准备好”的执行环境再复制

当前内部包没有通用下载即运行入口，现有命令仍需要准确的本机配置目录、容器名和 HA 地址。**这些由本机维护者先准备，不要求住户拼 URL、改路径、版本号或 hash。**

维护者应先核验固定包来源和独立 SHA-256，并在**这个 Terminal 会话**准备好兼容运行环境及本机参数。未准备好、只有一个压缩包或来源不明时，先停在这里，不尝试填写占位符。下面的命令不会自动猜这些信息，也不会安装或升级主机 Python。

<details>
<summary>给本机维护者：现有 CLI 的准备条件</summary>

本轮已验证的是 Linux Docker 参考环境，不代表所有 NAS 或非 Docker 环境。使用已核验的固定包、兼容 Python 3.14 执行环境和所需依赖；`python` 必须指向这个环境，不能把主机 Python 3.13 当作已验收运行时。既有参考验证使用固定官方 HA 镜像的一次性执行环境，没有升级主机 Python。

在住户将执行命令的同一会话中，准备以下非秘密环境变量：

| 变量 | 从本机实际配置取得的值 |
|---|---|
| `NEXHOME_PACKAGE` | 已核验固定包的解包目录，可导入现有 launcher/installer |
| `NEXHOME_HA_CONFIG` | 所选现有 HA 的实际配置目录 |
| `NEXHOME_HA_CONTAINER` | 对应现有 HA Docker 容器名称 |
| `NEXHOME_HA_URL` | 当前这台 HA 的可访问地址 |

这些是文档中对**现有 CLI 参数的传递**，不是已开发的自动检测器或新的安装程序。由维护者核对实际容器映射、Docker 权限和访问路径，不复制测试 VM 的路径、地址或凭据。没有安全的本机执行环境就不运行。

临时 HA 授权按现有隐藏输入提示提供；如使用受限临时文件，由维护者遵守现有权限和撤销流程。授权不写入这些环境变量或命令参数。当前一般安装不自动接管不明来源/HACS，冲突按既有受支持交接流程处理。

</details>

### B3. 复制第一行：进入已经核验的包目录

点代码块的复制按钮，复制**完整一行** → 粘贴到 Terminal → 按回车：

```sh
cd -- "${NEXHOME_PACKAGE:?请先让本机维护者准备安装环境和参数}"
```

正常会回到输入提示符，不会安装设备。若提示尚未准备、目录不存在或权限不足，停止，让维护者处理；不用自己改命令。

### B4. 复制第二行：只检查和预览

仍是复制完整一行 → 粘贴 → 回车：

```sh
python -m neighbor_launcher.bootstrap --config "${NEXHOME_HA_CONFIG:?请先让维护者准备本机配置路径}" --package "$NEXHOME_PACKAGE" --container "${NEXHOME_HA_CONTAINER:?请先让维护者准备本机容器参数}" --ha-url "${NEXHOME_HA_URL:?请先让维护者准备本机HA地址}"
```

正常会先提示输入这台 HA 的临时访问授权；输入时不显示内容。它不是中控 SN，不发给维护者或聊天。随后应看到检查/预览结果，**此步不部署**。如果提示来源冲突、不兼容或恢复未完成，就停下；不要连续重试。

### B5. 复制第三行：核对预览后确认安装

确认预览针对的就是这台 HA，且已有备份，再复制完整一行 → 粘贴 → 回车：

```sh
python -m neighbor_launcher.bootstrap --config "${NEXHOME_HA_CONFIG:?请先让维护者准备本机配置路径}" --package "$NEXHOME_PACKAGE" --container "${NEXHOME_HA_CONTAINER:?请先让维护者准备本机容器参数}" --ha-url "${NEXHOME_HA_URL:?请先让维护者准备本机HA地址}" --confirm
```

正常会检查、备份并部署，必要时短暂重启**指定的这台 HA**，随后给出自己的 HA 连接入口。已有版本相同且文件一致时可能提示无需更新；不要因此删除已有配置。不会创建新 HA，也不会重启全部 Docker 服务。

打开程序给出的链接，接着按第四、五节完成 HA 原生确认、查看设备和第一次控制。终端显示“部署完成”或退出码 0，不等于家里的设备都已验证。

### B6. 第一次设备操作完成后，复制最后一行检查完成状态

完成第五节的一盏灯开关和实际状态核对后，回到**同一个已准备会话**复制完整一行 → 粘贴 → 回车：

```sh
python -m neighbor_launcher.bootstrap --config "${NEXHOME_HA_CONFIG:?请先让维护者准备本机配置路径}" --package "$NEXHOME_PACKAGE" --container "${NEXHOME_HA_CONTAINER:?请先让维护者准备本机容器参数}" --ha-url "${NEXHOME_HA_URL:?请先让维护者准备本机HA地址}" --verify-completion
```

这一步只检查首次控制读回证据，并确认已经找到设备，**不会发送设备命令**。证据不足时不会完成；回到设备页核对，不重复部署。完成后终端可以退出，组件运行不依赖这个终端。临时授权按本机维护者的既有流程撤销、删除。

已知提示差异：当前冻结包有时在 READY 后仍附通用“继续连接”说明；以完成核验结果为准，已有 entry 不重复添加，不因这句说明重装。

**不要回头执行 App 安装；A/B 最终使用的是同一个 0.1.0。**

<a id="connect-home"></a>
## 四、连接家里的NexHome

### 新安装

点击连接入口后，HA可能先问“您想要设置此集成吗？”，点“确定”进入。随后自动查找：只有一个中控时，核对后点“提交”；多个时先选择自己的中控，再确认。系统不会静默替您添加未知中控。完成后可以在“命名和分配”页面整理设备，或点“跳过并完成”稍后整理。

没有找到时，可以重试，确认HA与中控网络可达。只有直接入口无效时才用最后的备用路径：**设置 → 设备与服务 → 添加集成 → NexHome 滨融府友邻加强版**。高级手动参数只在确实需要时由维护者协助，不作为普通流程。

![原生连接窗口](manual-images/native-confirm.png)

### 已经用过官方或旧版组件

**不要删除原来的NexHome。** 正常升级沿用原配置、名称、隐藏状态、房间和引用，不重新发现一个重复中控。如果原连接离线，应先检查原因，不要靠删除重建“解决”。HACS管理的安装会要求按正常HACS界面交接更新责任，保留HA里的条目。

## 五、第一次看到并控制设备

1. 打开 **设置 → 设备与服务 → NexHome 滨融府友邻加强版**。
2. 点设备数量或设备列表，找到“客厅主灯”等自己的设备。
3. 打开设备的控制项，先对一盏合适的灯开一次、关一次。看实际灯是否动作，并确认HA状态随后一致。
4. 回安装助手点“检查连接与首次操作”。真实状态已读回后，确认“我已找到设备并完成首次操作”，才显示安装与首次使用完成。

终端路线同样先按原生链接进入设备并完成第一次操作，不把终端退出码0当成所有设备已经可用。助手机器人不会为了点亮“完成”而自动开关家里设备。

![集成和设备列表](manual-images/devices.png)
![第一次灯光操作](manual-images/first-control.png)
![完成首次使用](manual-images/ready.png)

### 在自己的首页添加控制卡片

默认概览能自然显示部分设备；已有自定义页面不会被本项目改动。要自己整理时，先到 **设置 → 仪表盘 → 添加仪表盘 → 从新建仪表盘开始**，取名“NexHome”，按提示填页面地址并创建。

打开新页面，点编辑铅笔 → 添加卡片 → 按实体，搜索并选择一盏灯或窗帘，点击建议的“磁贴”卡片添加，最后点页面上方“完成”。已有可编辑页面可直接添加，不必重复新建。先放常用设备，不必一次整理全屋。

![添加设备卡片](manual-images/dashboard.png)

没有位置反馈的窗帘可能显示unknown/未知，仍可明确开/关/停；不要据此填一个假的百分比。

## 六、装好以后，推荐先做这5件事

### 1. 整理房间

到 **设置 → 区域、标签与地点 → 区域** 建立“客厅”“书房”等房间；再进入设备页选择所属房间。房间只是帮助找设备，不会改变线路。先整理两个常用房间即可。

![整理房间](manual-images/areas.png)

### 2. 建一个“客厅灯”设备组

打开 **设置 → 设备与服务 → 辅助元素 → 创建辅助元素 → 群组 → 灯组**。取名“客厅灯”，选择客厅主灯，用“添加实体”继续选择灯带、射灯，再点“提交”和“完成”。保持“所有实体”关闭，这样只要一盏亮着，灯组就显示开启。以后点一次控制整组；成员只选同一房间实际展示的灯，别把底层隐藏开关重复加进去。

![建立灯光组](manual-images/group.png)

### 3. 建一个“观影模式”场景

打开 **设置 → 自动化与场景 → 场景 → 创建场景**。在“实时编辑”中添加客厅主灯、灯带、窗帘，再按想要的状态调好。添加后可切换“预览模式”查看细节；预览模式不能新增成员。最后点“保存”，命名“观影模式”。示例为主灯关闭、灯带打开、窗帘关闭。

场景是“一次把几台设备变成想要的样子”。点场景或一句语音就可触发。**在真实环境编辑场景时，界面操作可能立即影响选中的设备，先确认家人方便再试。**

![观影模式场景](manual-images/scene.png)

### 4. 建时间/日落自动化

自动化可以理解为三个部分：**何时发生 → 满足什么条件 → 做什么事**。从设置 → 自动化与场景 → 创建自动化 → 创建新的自动化开始，按下面例子逐项选择，不需要写代码。

![自动化编辑入口](manual-images/automation.png)

#### 示例1：每天早上07:00开指定窗帘

1. 添加触发条件，选择“时间”，再选“在特定时间或特定日期触发”的“时间”，填07:00。
2. 添加动作，选择“打开窗帘”，目标只选要开的那一组。
3. 保存为“早上开客厅窗帘”。第一次手动运行时在现场观察，确认没有选错。

![选择时间触发](manual-images/time-trigger.png)

#### 示例2：工作日早晨开卫生间灯，再按时关闭

拆成两条最容易理解：

- “工作日早灯”：触发时间06:50；条件选择“时间”，只勾周一到周五；动作“打开灯”，选指定灯。
- “工作日关早灯”：触发时间07:30；同样的工作日条件；动作“关闭灯”，选同一盏灯。

保存前看清目标，不要选成整个房间的灯组。图中用通用测试灯示意，不在私密房间实测。

#### 示例3：每天太阳落山后关窗帘

1. 添加触发条件，选择“太阳”，再选“日落（日落时触发）”；不填固定18:00。
2. 添加动作“关闭窗帘”，选目标。
3. 保存为“日落关客厅窗帘”。

HA会按每天日落时间触发，因此需要“家”的大致位置正确；夏天、冬天的日落不同。[官方触发器说明](https://www.home-assistant.io/docs/automation/trigger/#sun-trigger)

![日落触发](manual-images/sun-trigger.png)

### 5. 开启手机定位，试回家/离家自动化

先按后面的“在手机上使用”登录，再按“家与定位”检查权限和家范围。先观察几天在家/离家显示是否可信，再允许自动关整屋灯。不是先写自动化再等定位“自然准确”。

## 七、在手机上使用

**iPhone和Android用户请安装官方Home Assistant App。**

安装后，登录自己的Home Assistant，就可以在手机上查看和控制已经接入的NexHome灯光、窗帘、空调等设备。后面的定位、到家/离家自动化和通知功能，也都通过Home Assistant App完成。

- iPhone：[官方App Store入口](https://apps.apple.com/app/home-assistant/id1099568401)，名称Home Assistant。
- Android：[官方Google Play入口](https://play.google.com/store/apps/details?id=io.homeassistant.companion.android)，名称Home Assistant。
- 也可从[官方移动端下载页](https://companion.home-assistant.io/download/)进入；无法访问对应商店时先查官方说明，不安装同名来历不明的软件。

![认准官方Home Assistant App](manual-images/official-app.png)

第一次在家中Wi-Fi打开App，选择自己的HA；没找到时输入自己原来能打开的HA地址，使用自己的HA账号登录。登录后的控制页面就是自己的HA页面。

如果希望使用“到家自动开灯”“全家离家后自动关灯”，下一节会介绍必要的位置权限。这里先完成下载和登录即可。[官方首次登录说明](https://companion.home-assistant.io/docs/getting_started/)

## 八、家与定位：先观察，再自动化

### 设置“家”

打开 **设置 → 区域、标签与地点 → 地点**，编辑“家/Home”。把中心放在自己家的大致位置，范围可以先设约100米，再根据实际定位表现调整。不要把测试图中的示意位置照搬到家里。

![设置家的范围](manual-images/home-zone.png)

100米是示例范围，不是绝对精度。GPS、手机系统后台、节电设置和网络都会影响及时性；坐在家里却显示离家时，先检查定位和家庭区域，别急着执行自动关灯。

### 给手机必要权限

- iPhone：系统设置 → 隐私与安全性 → 定位服务 → Home Assistant；按系统提示允许后台所需的位置权限、精确位置。后台功能一般需要“始终”，界面可能先询问“使用期间”再询问“始终”。
- Android：Home Assistant的应用权限中允许需要的位置/后台定位，并检查应用里的位置追踪开关及节电限制；不同厂商菜单不同。
- 每位成员用自己的账号和手机；在HA“人员”里将对应手机关联给对应人员。只观察到一个手机，不能代表全家。

离家时，手机还需能把状态传回HA；远程访问未打通或VPN断开，位置更新可能延迟。[官方定位说明](https://companion.home-assistant.io/docs/core/location/)

### 示例4A：夜间回家开客厅灯

1. 触发器选“区域”，对象选自己的人员，区域“家”，事件“进入”。
2. 条件选“状态”，选择“太阳”，状态选“地平线以下”（表示夜间）。
3. 动作选“打开灯”，目标“客厅灯”。
4. 保存后先观察定位变化和自动化运行记录，确认没有反复误触发。

### 示例4B：所有家庭成员都离家后关灯

**多成员家庭不能只用“我的手机离家”就关闭全屋灯。**

1. 先确认每位常住成员都正确关联手机；有人没带手机、定位离线或未纳入名单时，不启用整屋关闭。
2. 触发器用“家区域人数变为0”，可加持续几分钟后再判断。
3. 条件再次核对每位成员明确处于离家；unknown/unavailable不能当作离家。
4. 动作只选核对过的灯组，先从客厅试起。客人或保洁可能仍在家时，加手动“暂停离家自动化”的开关，或保持手动控制。

单人家庭也先验证自己的定位可靠。人员/区域人数条件需要本户实际名单和权限；本轮只验证编辑界面与逻辑，没有以真实手机离家做现场验收。

## 九、通知

在手机允许Home Assistant通知权限后，自动化动作里选择对应手机的“发送通知”，先只给自己发一条“测试通知”。确认目标手机正确，再加到需要的自动化里。不要把设备故障告警误发给所有家庭成员。本文不替您创建通知或改变已有摄像头通知。

## 十、用语音控制家里的设备

友邻加强版只增强HA接入，不主动修改开发商NexHome Hub或原有语音系统，设计目标是原控制方式继续正常。**当前没有对应语音中控实机，待邻居真实环境验证，不能写成兼容已通过。**

未来获得单独试点授权后，检查表应记录安装前品牌/型号、可控设备、示例命令；安装后重复相同命令，逐项确认。本轮不启动Pilot。

## 十一、出门以后还能用吗？

如果已经能在外面打开自己的HA，已接入设备仍从那里操作。如果只能在家Wi-Fi用，需要单独解决HA远程访问。

- 最省事：Home Assistant Cloud。
- 有NAS/服务器/域名：HTTPS及反向代理。
- VPN类：Tailscale、WireGuard或自己已有VPN。
- Tunnel类：Cloudflare Tunnel等，需要自行评估账户、认证和服务边界。

这里不展开网络部署教程。友邻加强版不自动改路由器、不自动开公网端口、不自动建立远程控制通道。远程访问方案和手机实机联动本轮未现场验证。[HA官方远程访问说明](https://www.home-assistant.io/docs/configuration/remote/)

## 十二、安全与遇到问题

先用灯、窗帘、普通场景练习。门锁、燃气、大功率电器和无人时运行的设备不作为新手自动化示例。多成员在家判断、手机定位误差、设备离线都应按“不确定”处理，不自动推断安全。

- 没找到中控：重试并检查家庭网络；不扫描全网、不擅改路由器。
- 已有条目不可用：保留原条目，先检查连接；不删除重建。
- 显示组件部署成功：继续连接和首次操作，不反复重装。
- 控制未确认：看设备真实状态，不靠一直点击重试；记录脱敏错误给维护者。
- 恢复未完成：停止操作，保留备份；不要认为换回代码一定能撤销所有设置变化。

不要发送密码、token、完整SN/IOTID、家庭成员或精确位置截图。手册图片只展示测试数据。自定义Dashboard、房间和自动化都由您自己决定是否修改。
