# 隐私与安全：让您放心地本地接入

**当前状态：Community Candidate 仅完成离线验证，尚无正式安装器或 Release。** 这份说明是实现必须遵守的设计原则，不是声称某个已发布软件已经通过全部验收，也不是法律协议。当前验证范围见 [Review Gate](phase1-review-gate.md)。

Neighbor Edition 的目标是帮助您把**自己家的 NEXhome 设备接入自己家的 Home Assistant**。安装不应意味着把家里的控制权交给项目维护者。

## 设备信息在哪里处理

默认情况下，中控发现、配置、状态读取与控制，都发生在您自己的家庭网络和 Home Assistant 中。

工具不会默认上传灯光、空调或窗帘状态，也不会默认上传家庭成员、人员在家情况、家庭位置、自动化历史或设备使用记录。不默认开启统计、遥测或日志回传。

Home Assistant 为本地通讯需要保存的中控标识，可以留在您自己的配置里；不会因此自动发送给维护者或放进公开日志。

## 谁能访问您家的设备

控制仍由您自己的 Home Assistant 账号、权限和家庭网络决定。

Neighbor Edition 不会因为安装而为项目维护者、邻居、开发者或 GitHub 建立远程访问权限。不创建项目方远程账号、共享管理员、反向隧道或维护后门。

您原来自己配置的远程访问是另一回事，工具不会擅自改变它，也不把它变成项目方的访问通道。

## 您不需要把密码发给任何人

不要向维护者提交 HA 密码、长期访问 token、完整 IOTID/SN、Wi-Fi 密码或 NEXhome 凭据。工具也不应要求您这么做。

必要的 Home Assistant 授权在您自己的设备上完成，不保存您的 HA 密码。其他本地授权凭据只按本次任务需要处理，并提供结束/撤销方式，不写入诊断或更新请求。

如果有人以“帮助安装”为由要求私发密码或 token，请不要发送。本项目不需要这些资料通过聊天、Issue 或邮件交给维护者。

## 为什么可能需要管理权限

安装或更新组件、建立本地备份、必要时重启 HA，可能需要管理权限或本机部署权限。

工具必须先说清楚用途，并展示具体变更。它不能只写“授权全部权限”，也不能假称 HA 管理员授权本身被技术上限制成一个不存在的细粒度权限。

一个合适的提示是：“需要 Home Assistant 管理权限，用于本次安装/升级 NEXhome 组件和创建本地备份；如需重启，会提前说明。”

## 不偷偷改您家的布局

默认安装不修改现有 Area、Dashboard、Automation、家庭成员、presence、用户账号或网络设置。

将来可选的户型/页面向导，必须先显示建议、让您确认后才应用。多个同名灯具不会仅凭名称自动分房间。

## 更新前让您知道

首版计划：显示可用版本、说明将做什么、是否需要短暂重启、如何恢复，由您点击确认后才升级。不会后台静默升级。

每个实例只由一个系统管理 NEXhome 更新。HACS 管理时，Installer 不同时替换文件；需要切换来源时先说明、备份、核验，不能留两套更新系统互相覆盖。

下载文档或发行包、由您主动检查更新时，会连接 GitHub 或相应分发服务。服务方可能看到请求 IP 等普通访问记录；请求不得携带您的中控标识、设备状态或家庭历史。这与上传家庭设备信息是不同的事情，工具必须如实解释。

## 诊断由您主动导出

遇到问题时，计划提供一个导出脱敏诊断的入口，减少手抄日志。

诊断包只在您主动导出时生成，默认不上传。先让您预览，再由您决定是否分享。默认剔除完整设备标识、token、密码、精确位置、设备名称和不必要的网络信息。

完整恢复备份可能含敏感配置，只保存在您控制的位置并单独保护，不能把它误当成可分享诊断。

## 失败后尽量恢复原状

升级前建立可用恢复点；失败时尽量自动恢复旧组件和更新所有权，并核对原配置仍可用。

如果断电、宿主不可达或权限限制导致无法自动恢复，工具应给您一个清晰的恢复入口和具体下一步，不把“请自行 SSH 修复”当作面向普通用户的默认处理方式。工具不得把尚未完成的恢复显示为成功。

## 完成时应该看到什么

只有对应检查通过后，才显示“已完成本地接入”，并说明：

- 不建立第三方远程控制。
- 不上传设备状态。
- 不保存您的 HA 密码。
- 默认不改变现有 Area、Dashboard 和 Automation。

您另外确认过的可选变更，要如实单列。无论是否安装此项目，您始终是家庭设备和数据的控制者。
